# 異常場所檔案館：擴充計畫

## 北極星

把目前三個各自成立的短篇，做成一座能反覆調閱的檔案室：每個場所先獨立
好玩、能完整結案；玩過的人才會慢慢發現，文件、時間與「下一個值班者」正在
跨場所互相指認。世界觀不是解謎百科，線索永遠是額外的第二層。

## 已有基礎

- 三份卷宗：深夜飯店、夜班櫃台、深夜便利商店。
- 首頁有結案記錄、原件調閱與檔案室異變；不需要另造一套 meta 系統。
- 場景契約已把規則、事件、預言、時間模型及存檔隔離好；新場所不該為了劇情
  把飯店特例塞進引擎。

## 第一階段：把「系列」補成可持續玩的骨架（完成）

1. **完成夜班櫃台的三晚曲線** ✅
   - 第一晚的選擇留下可讀的交班紀錄。
   - 第二晚讓昨晚的後果回寫成文件異動，而非單純加難度。
   - 第三晚讓玩家面對自己的名字；三晚結局成為真正的長線回報。
2. **新增第四份獨立卷宗：末班公車** ✅
   - 不是飯店支線；主題是「錯過／上錯／被班表記住」。
   - 用 cycle 時鐘測試跨午夜的通用契約，避免再生一套時間 bug。
3. **補內容驗證守門員** ✅
   - 每一場至少保留兩條可達結局路徑與一條超時路徑。
   - 時間戳、預言、事件窗與結局條件由測試共同鎖住。

## 第二階段：卷宗開始互相說話（首輪完成）

4. 新增第五、第六場所，刻意換掉「值夜班」的職業視角：停業診所與地下
   洗衣店均已完成。每場各自有一個不可替代的玩法動詞。
5. 將結案單上的少量內容轉成**線索索引**：歸檔原件與最近結局只顯示玩家已經
   看過的內容，不劇透、不強迫全收集。
6. 讓第四十四號檔案室在六份卷宗後開出一段可反覆閱讀的管理員記錄；它是收束，
   不是第七個把所有答案講破的關卡。

## 實作原則

- 一次只推一個場所或一晚內容；每段都有場景測試與全站路徑驗證。
- 場景資料維持自含，`engine.js` 只接通用能力。需要為單一故事改引擎時，先證明
  至少兩個場所會用到它。
- 互相指認用重複物件、措辭與時間，而不是角色百科或硬塞設定。
- 不改動既有存檔語意時不 bump 版本；若 state 形狀實質不相容，明確 bump storage
  version，寧可重開也不要半壞存檔。
